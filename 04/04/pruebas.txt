Interpretación:

- 22/TCP: sshd (PID 1153). Administración remota.
- 80/TCP: docker-proxy (PID 4079 IPv4, 4085 IPv6). Publica el puerto de Nginx.
- 5000/TCP: no aparece en el host. Flask solo existe en la red interna de
  Docker porque el compose final usa expose, no ports.
- 5432/TCP: no aparece. PostgreSQL no está desplegado en esta instancia.
- 53/UDP y 53/TCP: systemd-resolved, DNS local. No es un servicio público.
- 323/UDP: chronyd, sincronización de hora local.
- 68/UDP: systemd-networkd, cliente DHCP de la interfaz ens5.

== 4. Prueba desde Internet ==

$ curl.exe http://54.152.85.71/health
{"status":"ok"}

$ curl.exe http://54.152.85.71:5000/health
curl: (28) Failed to connect to 54.152.85.71 port 5000 after 21039 ms: Could not connect to server

Conclusión de la prueba:

- El puerto 80 sigue funcionando a través de Nginx.
- El puerto 5000 ya no es accesible desde Internet: no está publicado en el
  host y además se eliminó la regla del Security Group.
- El único punto de entrada público es Nginx en el puerto 80.
- PostgreSQL (5432) nunca se expuso.

== 5. Propuesta de mínimo privilegio ==

| Regla | Puerto | Protocolo | Origen | Justificación |
|---|---:|---|---|---|
| SSH administrativo | 22 | TCP | IP administrativa/32 | Acceso remoto controlado |
| HTTP | 80 | TCP | 0.0.0.0/0 (o My IP en el laboratorio) | Entrada web pública |
| HTTPS | 443 | TCP | 0.0.0.0/0 | TLS en producción (futuro) |
| Flask | 5000 | — | Sin regla | Solo red Docker interna |
| PostgreSQL | 5432 | — | Sin regla | Solo red Docker/privada |

El resultado esperado es:

    Internet -> 80/443 -> Nginx -> Flask:5000 (interno)
    Administración -> 22 -> IP autorizada
    Internet -X-> 5000
    Internet -X-> 5432
